## Bước 1 — Picker: 3 class var config + `ExpandToPath`
Var mới trên `WBP_FolderTreePicker`:
| Tên | Kiểu | Default |
|---|---|---|
| `CurrentPath` | String | "" |
| `bShowCurrentTag` | Boolean | false |
| *(SelectedPath đã có — tái dùng)* | | |

Function mới `ExpandToPath(Path : String)` — mở sẵn đường tới 1 path (dùng cho Move mở tag "hiện tại", Card 2 tái dùng cho folder mới tạo). Logic = vòng trong của `BuildSearchOverride` nhưng ghi vào `ExpandedFolders` và add CẢ path cuối:
```
Local: Segments (Array<String>), AccumPath (String)
▶ ParseIntoArray(Path, "/", CullEmpty=✓) → SET Segments
▶ SET AccumPath = ""
▶ ForLoop(0 → Segments.LastIndex):                ← khác BuildSearchOverride: chạy tới hết (không -2)
     Branch(Index==0) True→ AccumPath=Segments[0]
                      False→ AccumPath=Concat(AccumPath,"/",Segments[Index])
     [merge] → Array_AddUnique(ExpandedFolders, AccumPath)
  Completed → hết hàm (KHÔNG tự gọi RefreshVisibleRows — caller quyết định lúc render)
```
Guard: `Path==""` → ParseIntoArray trả rỗng → ForLoop không chạy → no-op an toàn.

**[Q1 — CHỐT] Vì sao chạy tới `LastIndex` (add cả CHÍNH path), khác `BuildSearchOverride` (n-2)?** CHỦ ĐÍCH, không phải bug:
- **Move:** `CurrentPath` tự mở → con của nó (= ANH EM của item đang move) lộ sẵn — đây là các đích move tự nhiên nhất, UX thắng.
- **Save create (Card 2):** `ExpandToPath(NewFolderPath)` — folder mới là LEAF, add chính nó vào `ExpandedFolders` = no-op vô hại (`IsPathVisible` chỉ kiểm tổ tiên, leaf không có arrow — đúng bản chất đã chốt ở comprehension check 12/07).
- Đơn giản hơn 1 nhánh đặc biệt. KHÔNG đổi thành n-2.
