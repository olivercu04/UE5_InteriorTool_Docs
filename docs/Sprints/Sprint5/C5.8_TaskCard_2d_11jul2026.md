## Mục tiêu

Cho `WBP_FolderPickerRow` có khả năng inline-rename (giống `WBP_TreeNode`/`WBP_ChipTag` đã làm ở C5.2/C5.7b), và cho `WBP_FolderTreePicker` 1 hàm `BeginRenameOnPath(Path, Siblings)` để tìm đúng ROW trong SB_Rows của CHÍNH picker rồi kích rename mode.

**Vì sao cần:** flow Create Folder (§6, dùng ở Wire Save) sau khi tạo "New Folder (N)" phải tự đưa row đó vào rename mode + bôi đen text để user gõ đè. `OnRequestNewFolder` cũ của inventory KHÔNG dùng được vì đuôi nó hardwired vào `VerticalBox_44` (cây inventory, không phải picker). → picker cần twin riêng.

## Bối cảnh tái dùng (KHÔNG viết lại — chỉ nối)

`WBP_EditableLabel` (v1.0) đã là component HOÀN CHỈNH, tự lo:
- `EnterEditMode(Siblings)` — Delay(0.0) + focus + select-all.

→ 2d chỉ cần: (1) host `WBP_EditableLabel` trong row (thay `TXT_Name` hiện tại), (2) relay + bind y hệt `WBP_TreeNode` v1.3, (3) picker tìm row + gọi relay.

## PHẦN 2 — WBP_FolderTreePicker: BeginRenameOnPath

### 2a. `BeginRenameOnPath(Path : String, Siblings : Array<String>)` — Function
Tìm ROW trong `SB_Rows` có `RowNode.Path == Path`, gọi `EnterRenameMode(Siblings)` của nó.
**Local var:** Children (Array<Widget ref>), RowRef (WBP_FolderPickerRow ref), bFound (Bool)
```
▶ SET Children = Get All Children(SB_Rows)
▶ SET bFound = False
▶ ForEachLoopWithBreak(Children):
     LoopBody (Element, Index):
       ▶ Cast Element → WBP_FolderPickerRow → RowRef
          Cast Failed → [dead-end, tiếp loop]
          Cast OK →
            ▶ Branch( RowRef.RowNode.Path == Path )   ← Array Contains KHÔNG dùng; so 1 String exact
               True  → RowRef.EnterRenameMode(Siblings)
                        SET bFound = True
                        ▶ Break
               False → [dead-end, tiếp loop]
     Completed →
       ▶ Branch(NOT bFound)
          True → Print("BeginRenameOnPath: không tìm thấy row " + Path)   ← gate bDebugMode
          False → [dead-end]
```
> Q8: Container=Function | IsValid: Cast + branch trước mọi access RowRef.RowNode | L2: mọi nhánh LoopBody dead-end hợp lệ (trong loop, không Event chain), Completed có Branch → 2 nhánh có đích | No latent (ForEachLoopWithBreak không latent, hàm hợp lệ) | 6A: n/a — utility mở rename
> **Vì sao tìm trong SB_Rows chứ không VerticalBox_44:** đây là điểm khác cốt lõi so với `OnRequestNewFolder` cũ — picker chỉ đụng con của CHÍNH nó, không đụng cây inventory (đang bị dialog che).
> ⚠️ Nếu `RowNode` chưa public/không đọc được từ ngoài → thêm getter `GetRowPath() → String` trên row, dùng thay `RowRef.RowNode.Path`. Confirm khi build.

### 2b. Relay commit lên vỏ (chuẩn bị cho Wire Save)
Trong `RefreshVisibleRows`, chỗ Bind mỗi row (đã có `Bind OnRowExpandClicked`/`OnRowSelected`), THÊM:
```
▶ Bind Row.OnRowRenameCommitted → HandleRowRenameCommitted
```
### 2c. `HandleRowRenameCommitted(Path, NewName)` — Custom Event (bound)
```
▶ Broadcast OnRequestCommitRename(Path, NewName)
```
> Dispatcher mới `OnRequestCommitRename(OldPath, NewName)` — vỏ Save bắt ở Wire Save (task sau) để gọi `RenameFolderPrefix`. 2d chỉ dựng đường ống, CHƯA nối tới backend rename (đó là việc Wire Save §6).
> Q8: Custom Event | L2: tuyến tính | No latent | 6A: n/a

## PHẦN 3 — TEST (2d độc lập, chưa cần Wire)

Test tạm bằng cách gọi thủ công (nút test hoặc từ `RefreshVisibleRows` gắn tạm), CHƯA cần vỏ Save thật:

```
1. Gọi picker.BeginRenameOnPath("Livingroom", [siblings]) → row Livingroom vào edit mode,
   text bôi đen sẵn, EditBox nhận focus.
2. Gõ tên mới hợp lệ + Enter → OnRowRenameCommitted fire (Print Path + NewName đúng).
   → OnRequestCommitRename fire ở picker (Print).
3. Gõ tên trùng sibling → Border_Error hiện "Tên đã tồn tại", KHÔNG commit (WBP_EditableLabel tự lo).
4. Gõ tên chứa "/" → Border_Error "Tên không chứa ký tự /".
5. Đang edit → click ra ngoài (focus out) → ExitEditMode(revert), text về cũ, KHÔNG fire commit (6A — đường ngược).
6. BeginRenameOnPath với path KHÔNG tồn tại trong cây đang hiện → Print "không tìm thấy", không crash.
7. Rename tên tiếng Việt có dấu ("Phòng Ngủ") → commit đúng, không vỡ dấu.
```
> Mục 5 = 6A must-have (đường ngược của rename). Mục 3/4 chứng minh validate của EditableLabel còn hoạt động qua host mới.
