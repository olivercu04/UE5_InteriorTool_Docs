## PHẦN 3 — QUYẾT ĐỊNH KIẾN TRÚC

**Hướng: cắt 3 dây → migrate tool sang project sạch → package.**

Vì sao chạy:
```
Cast thẳng Foff_GameInstance  → kéo master vào cook → 729 lỗi
Gọi qua Interface             → tool KHÔNG biết GameInstance nào → không kéo gì
Migrate sang project sạch     → master junk KHÔNG TỒN TẠI → lỗi không thể xảy ra
```

Đây là cách đồng nghiệp đã chứng minh: mỗi người code riêng project, giao tiếp qua interface, ai cũng package được.

**Interface = bản hợp đồng.** Tool chỉ đòi "ai đó biết làm việc X", không cần biết class cụ thể. Đổi project = không sửa code tool → merge về master không phải sửa lại lần 2 (giải quyết đúng lo ngại "mất công 2 lần").

**Giá phải trả (nói thẳng):** đây là task NHIỀU NGÀY, không phải vá vài giờ. Gate 1.5 gốc (smoke test nhanh) nhập luôn vào việc migrate. Nhiều bước: cắt 3 dây + migrate + rebuild 2 plugin C++ + dựng lại host tối giản.

**Lưới an toàn:** lúc bấm Migrate, UE hiện danh sách đầy đủ asset nó định copy. Thấy Procedural/KitchenPro trong list = còn hidden ref chưa cắt → lộ ngay, không cần đoán.
